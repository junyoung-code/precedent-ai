# 안전한 사례 입력 흐름 설계

- 작성일: 2026-08-16
- 상태: 사용자 승인 완료, 구현 계획 작성 전
- 대상: 비공개 판례AI 프로토타입

## 목표

사용자가 사례 설명과 대화 캡처를 안전하게 검토한 뒤, 검색에 필요한 최소 사실만 임시 세션으로 제출하고 판례 검색 후 즉시 삭제할 수 있게 한다. 이 단계에서는 이미지나 전사 내용을 외부 OCR·AI 서비스에 보내지 않는다.

## 범위

### 포함

- PNG, JPEG, WEBP 캡처의 브라우저 내 형식·10MB 크기 검증과 미리보기
- 사용자가 직접 입력·수정하는 전사 검토 영역
- 이름, 전화번호, 이메일, 계정명, 주소를 가리는 결정론적 개인정보 가림기
- 가려진 텍스트와 사례 설명에서 부족한 중립 사실을 최대 3개 질문하는 흐름
- 임시 세션 생성, 검색 완료·사용자 취소 시 즉시 삭제, 1시간 TTL 삭제
- 삭제 완료 여부를 확인할 수 있는 서버 응답과 테스트
- 외부 의미 검색 동의와 캡처/OCR 처리를 명확히 분리하는 UI 문구

### 제외 및 승인 대기

- 이미지 또는 전사문을 외부 OCR·Vision API로 전송하는 기능
- 독립 OCR 서버의 배포와 운영
- 실제 사용자 사건의 장기 저장, 계정, 이력
- 국가법령정보센터 정기 동기화, 배포, 모니터링, 백업

외부 OCR을 켜려면 이미지 전송 대상, 보관 기간, API 비용, 사용자 고지 문구를 사용자가 별도로 승인해야 한다.

## 사용자 흐름

1. 사용자는 역할과 사례 설명을 입력하고, 선택적으로 대화 캡처를 첨부한다.
2. 브라우저는 지원 형식과 10MB 제한을 확인하고 캡처 미리보기만 표시한다. 이미지 원본은 이 단계에서 서버로 전송하지 않는다.
3. 사용자는 캡처의 필요한 문장을 전사 검토 영역에 직접 입력하거나 붙여넣는다.
4. 앱은 전사문과 사례 설명에서 개인정보 후보를 표시하고, 사용자가 확인한 가림본만 세션에 보낸다.
5. 서버는 검색에 필요한 전달 매체·상대방 특정·도달 여부·관계·반복 여부 중 모르는 값을 최대 3개 질문으로 반환한다.
6. 사용자가 답하면 서버는 임시 세션의 가려진 사실만 사용해 기존 검색 API를 호출한다.
7. 결과 응답을 만든 직후 서버는 세션의 설명, 전사문, 가림본, 답변을 삭제한다. 사용자가 취소해도 즉시 삭제한다. 미완료 세션은 생성 1시간 뒤 정리 작업이 삭제한다.

## 구조

### 브라우저

`CaseComposer`는 이미지 미리보기와 전사 검토를 담당한다. `redactSensitiveText`는 표시와 제출 전 확인을 위한 순수 함수다. 브라우저는 이미지 파일을 검색 API나 임시 세션 API에 보내지 않는다.

### 서버

`intake-session` 모듈은 가려진 텍스트, 역할, 추출 사실, 질문과 답변만 저장한다. `POST /api/intake`는 세션을 만들고 질문을 반환한다. `POST /api/intake/:id/answers`는 답변을 검증하고 검색 가능한 상태를 반환한다. `POST /api/intake/:id/complete`와 `DELETE /api/intake/:id`는 즉시 삭제한다. `purgeExpiredIntakeSessions`는 1시간이 지난 세션을 삭제한다.

### 저장 원칙

- 세션에는 이미지 바이트, 파일명, 원본 사례 설명, 원본 전사문을 저장하지 않는다.
- 서버 로그에는 사례 내용, 전사문, 개인정보, 이미지 경로를 쓰지 않는다.
- 삭제는 멱등적이다. 이미 삭제된 세션을 다시 삭제해도 성공으로 응답한다.
- TTL 삭제는 종료 시각이 아니라 세션 생성 시각을 기준으로 최대 1시간을 넘기지 않는다.

## 개인정보 가림 규칙

가림기는 다음 유형을 `[가림]`으로 바꾼다: 한국 전화번호, 이메일, URL 형태의 계정 링크, `@`로 시작하는 계정명, 주민등록번호처럼 보이는 6-7자리 숫자 조합, 도로명 주소의 명시적인 번지 표현. 가림기는 법적 판단을 하지 않으며, 사용자가 전송 전에 수정할 수 있다.

## 추가 질문

질문은 중립 사실만 묻는다. 우선순위는 전달 매체, 상대방 특정 방식, 실제 도달 여부, 관계, 반복 여부다. 이미 명확한 값에는 질문하지 않고 최대 3개만 반환한다. 유무죄, 고소 가능성, 처벌, 대응 방법은 질문이나 답변에 포함하지 않는다.

## 오류 처리

- 잘못된 이미지 형식·초과 크기: 브라우저에서 막고 서버에 보내지 않는다.
- 세션 ID가 없거나 만료됨: `INTAKE_SESSION_NOT_FOUND`를 반환하고 새 입력을 안내한다.
- 질문 답변이 비어 있음: `INTAKE_ANSWER_REQUIRED`를 반환한다.
- 삭제 작업 실패: 서버는 오류 코드를 반환하고, 정리 작업이 다음 실행에서 다시 삭제한다. 같은 오류가 두 번 연속 발생하면 자동 재시도를 중단하고 운영자에게 보고한다.

## 검증 기준

- 파일 검증, 미리보기 제거, 가림기, 질문 수/내용, 만료 계산, 즉시·멱등 삭제를 단위 테스트한다.
- API 테스트는 원문이나 이미지가 DB 쿼리·응답·로그 인자에 포함되지 않는지 확인한다.
- 전체 테스트, production build, Sites 패키징을 통과시킨다.
