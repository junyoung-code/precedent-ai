# 판례AI 입력창 및 결과 전환 디자인

작성일: 2026-08-09

## 목표

현재 랜딩 화면에서 큰 AI 안내 카드와 별도의 역할 선택 카드가 차지하는 공간을 줄이고, 일반적인 AI 서비스처럼 넓은 입력창을 중심으로 사례를 입력할 수 있게 한다. 사용자는 입력창 하단에서 피해자 또는 피신고인 관점을 선택하고, 제출 후에는 별도 화면으로 갑자기 전환되지 않고 결과 영역으로 부드럽게 이동한다.

## 범위

- 랜딩 화면의 AI 고지 방식 변경
- 피해자ㆍ피신고인 역할 선택을 입력창 하단 토글로 이동
- 입력창 크기와 영웅 영역의 세로 간격 확대
- 제출 후 결과 영역으로 이어지는 부드러운 전환
- 기존 판례 검증, 순위 산정, 원문 링크, AI 요약 표시는 유지

백엔드, 판례 데이터셋, 검색 점수 로직, 첨부 파일 저장 방식은 변경하지 않는다.

## 법적 고지 원칙

이 서비스는 생성형 AI를 이용해 공개 판례의 요약이나 차이점 설명을 제공하므로 AI 사용 사실에 대한 사전 고지와 생성 결과 표시를 유지한다.

- 큰 `AI 사용 안내` 카드는 제거한다.
- 입력창 하단 또는 바로 아래에 사용 전에 읽을 수 있는 짧은 문구를 항상 표시한다.
  - `AI가 공개 판례를 검색·비교합니다.`
- AI가 생성한 판례 요약에는 기존 표시를 유지하고 문구를 명확히 한다.
  - `AI 생성 요약`
  - `정확한 내용은 공식 원문을 확인하세요.`
- `판례AI` 서비스명과 공식 원문 링크를 유지한다.

근거:

- 인공지능기본법 제31조: 생성형 AI 기반 서비스의 사전 고지 및 생성 결과 표시
- 인공지능기본법 시행령 제23조: 이용약관이나 이용자 화면을 통한 고지를 허용하고, AI 활용 사실이 명백한 경우 일부 적용 예외 가능
- 인공지능기본법 제43조: 제31조제1항의 사전 고지 미이행에 대한 과태료

이 명세는 법률 자문이 아니라 현재 시행 법령을 바탕으로 한 제품 설계 기준이다.

## 화면 구성

### 영웅 영역

- 의사봉 원형 이미지는 현재 크기와 스타일을 유지한다.
- 원형과 눈썹 문구 사이에는 16px 간격을 둔다.
- 눈썹 문구와 두 줄 제목 사이는 12px로 둔다.
- 제목과 보조 설명 사이는 18px로 둔다.
- 보조 설명과 입력창 사이는 52px로 넓힌다.
- 큰 화면에서는 전체 영웅 영역과 입력창 묶음을 화면 중앙에 배치한다. 720px 높이의 짧은 데스크톱에서는 영웅 위아래 여백만 줄이고 입력 카드 크기는 유지한다.

### 사례 입력창

- 데스크톱 최대 너비는 1,040px로 한다.
- 데스크톱 입력 카드의 최소 높이는 238px, 본문 입력 영역 높이는 150px로 한다.
- 입력창 전체를 하나의 큰 카드로 보이게 하고, 본문 영역과 하단 도구 모음을 내부 구분선으로 나눈다.
- 제목형 라벨은 제거하고 placeholder로 입력 목적을 안내한다.
  - `상황·매체·관계·횟수를 시간 순서대로 적어주세요.`
- 입력 중에는 외곽선과 배경색을 부드럽게 강조한다.

### 하단 도구 모음

왼쪽에서 오른쪽 순서로 다음 요소를 배치한다.

1. 대화 캡처 첨부 버튼
2. `피해자 | 피신고인` 세그먼트 토글
3. 남은 공간
4. 글자 수
5. 전송 버튼

세그먼트 토글은 한 번에 한 값만 선택할 수 있으며 선택된 항목은 브라운 배경과 흰색 글자로 표시한다. 선택하지 않은 상태에서는 두 항목 모두 중립색이며, 제출 버튼은 비활성화한다. 모바일에서는 첨부 버튼과 토글을 첫 줄, 글자 수와 전송 버튼을 둘째 줄에 배치한다.

### AI 고지

- 입력 카드 아래에 작은 정보 아이콘과 함께 `AI가 공개 판례를 검색·비교합니다.`를 표시한다.
- 법적 고지라는 이유로 강조 상자나 경고색을 사용하지 않는다.
- 개인정보 비저장 문구와 한 줄로 합치지 않고, 두 문구의 목적을 구분하되 시각적 중요도는 동일한 보조 텍스트 수준으로 둔다.

## 상호작용과 상태 전환

### 제출 전

- 역할이 선택되고 사례가 15자 이상 입력되어야 전송 버튼이 활성화된다.
- 첨부 파일 형식과 크기 검증은 기존 동작을 유지한다.
- Enter는 줄바꿈으로 사용한다. 제출은 전송 버튼 클릭으로만 처리한다.

### 제출 중

- 전송 버튼을 비활성화하고 `비교 중…` 상태를 표시한다.
- 입력 카드 아래에 짧은 로딩 상태를 표시한다.
- 기존 입력 내용과 선택 역할은 화면에 남긴다.

### 결과 표시

- 별도의 갑작스러운 화면 교체 대신 동일한 앱 셸에서 결과 영역을 입력창 아래에 렌더링한다.
- 결과가 준비되면 결과 제목으로 `scrollIntoView({ behavior: "smooth", block: "start" })`를 한 번 실행한다.
- 스크롤 시간은 브라우저 기본 부드러운 스크롤을 사용하며, 결과 카드에는 160~220ms의 짧은 투명도ㆍ위치 전환을 적용한다.
- `prefers-reduced-motion: reduce` 환경에서는 부드러운 스크롤과 카드 이동 애니메이션을 사용하지 않는다.
- 결과 화면의 `새 사례`는 입력과 역할을 초기화하고 영웅 영역으로 부드럽게 돌아간다.

## 컴포넌트 변경

- `AiDisclosure`: 랜딩용 큰 카드 사용을 제거하고 결과 화면의 필요한 고지만 유지한다.
- `RoleSelector`: 두 개의 큰 카드 대신 입력창 도구 모음에서 사용하는 세그먼트 토글 형태로 변경한다.
- `CaseComposer`: 역할 토글, 첨부, 글자 수, 전송을 하나의 하단 도구 모음으로 결합한다.
- `HomeView`: 영웅 영역과 입력 카드 사이의 간격을 확대하고 작은 AI 고지를 입력 카드 아래에 배치한다.
- `App`: 제출 후 결과 상태를 동일 문서 흐름에 렌더링하고 결과 시작 요소에 ref를 연결한다.

## 데이터 흐름

1. 사용자가 역할과 사례를 입력한다.
2. 기존 `ready` 조건이 역할과 15자 이상 입력을 확인한다.
3. 제출 시 기존 사실 추출 및 판례 순위 로직을 실행한다.
4. 결과 상태가 채워지면 결과 영역을 렌더링한다.
5. 렌더링 완료 후 결과 시작점으로 부드럽게 이동한다.
6. 공식 출처가 검증되지 않은 판례는 기존과 동일하게 표시하지 않는다.

## 오류 처리

- 역할 미선택 또는 15자 미만 입력: 전송 버튼 비활성화
- 지원하지 않는 첨부 형식 또는 10MB 초과: 기존 인라인 오류 표시 유지
- 유사도 기준을 통과한 판례 없음: 기존 판례 없음 상태를 결과 영역에 표시
- 스크롤 대상이 렌더링되지 않은 경우: 오류를 발생시키지 않고 현재 위치 유지

## 검증 기준

- 큰 AI 안내 카드와 별도 역할 카드가 랜딩에서 보이지 않는다.
- 작은 사전 고지 문구가 제출 전에 화면에 보인다.
- 각 AI 요약에 `AI 생성 요약`과 공식 원문 확인 문구가 보인다.
- 데스크톱 입력 카드 최대 너비가 1,040px이고 입력 본문 높이가 150px이다.
- 피해자ㆍ피신고인 토글이 입력 카드 하단에서 동작한다.
- 역할과 15자 이상 입력 전에는 제출할 수 없다.
- 제출 후 결과가 같은 문서 흐름에 나타나고 결과 시작점으로 부드럽게 이동한다.
- 모션 감소 설정에서는 이동 애니메이션을 사용하지 않는다.
- 1280 × 720 데스크톱에서는 영웅 여백이 축소되고 입력 카드의 핵심 조작부가 잘리지 않는다.
- 모바일에서는 자연스럽게 스크롤하며 도구 모음이 두 줄로 재배치된다.
- 검증된 판례, 공식 원문 링크, 법적 결론 비예측 문구가 유지된다.
