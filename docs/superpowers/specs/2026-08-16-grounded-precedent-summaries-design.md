# 근거 연결 판례 요약 설계

## 목표

검증된 공개 판례의 판결문 문단만 사용하여 판례별 중립 요약을 미리 생성하고, 모든 요약 문장을 동일 판례의 실제 문단 ID에 연결한다. 사용자 사례는 요약 생성 과정에 전달하지 않으며, 근거 검증에 실패한 요약은 서비스에 표시하지 않는다.

## 범위

- 국가법령정보센터에서 수집하고 출처 검증을 통과한 `searchable=true` 판례만 처리한다.
- `source_rights.summary_allowed=true`인 출처만 요약한다.
- 판례당 최대 3개의 핵심 문장을 생성한다.
- 사실관계와 법원이 중요하게 판단한 이유를 중립적으로 설명한다.
- 판결 결과 예측, 사용자 사건에 대한 판단, 신고·고소 가능성, 형량 예측은 생성하지 않는다.
- 사용자 입력, 역할 선택, 첨부 이미지는 요약 모델에 전달하지 않는다.

## 생성 시점

요약은 사용자 검색 요청 중에 만들지 않는다. 판례 동기화와 출처 검증이 끝난 뒤 운영자가 `npm run summaries:backfill`을 실행하거나 추후 정기 작업이 같은 모듈을 호출한다.

검색 요청은 저장된 검증 요약만 읽는다. 따라서 요약 생성 실패나 외부 AI 장애가 사용자 검색 API의 성공 여부와 응답 시간에 영향을 주지 않는다.

## 데이터 모델

`precedent_summaries` 테이블을 추가한다.

- `precedent_id`: 요약 대상 판례 ID, 기본 키이자 `precedents.id` 외래 키
- `source_hash`: 요약 생성에 사용한 판결문 원문 해시
- `summary_version`: 프롬프트와 검증 규칙 버전
- `model`: 생성에 사용한 모델명
- `sentences`: 검증 완료된 문장과 문단 ID 배열을 담은 JSONB
- `generated_at`: 생성 완료 시각

저장 형식은 다음과 같다.

```json
[
  {
    "text": "법원은 메시지가 전달된 경위와 대화의 전체 맥락을 함께 살폈습니다.",
    "paragraphIds": ["p-00012", "p-00013"]
  }
]
```

판결문 `source_hash`, `summary_version`, `model`이 모두 같으면 재생성을 건너뛴다. 판결문 해시가 변경되면 기존 요약은 검색 결과에 노출하지 않고 새 요약을 생성한다.

## AI 입력과 출력

AI 입력에는 한 판례의 다음 값만 포함한다.

- `paragraphId`
- 해당 문단의 판결문 본문

사건번호, 법원, 선고일, 공식 URL은 AI 입력·출력 스키마에 포함하지 않는다. 이 값들은 계속 검증된 판례 DB에서만 가져온다.

AI 출력은 다음 구조만 허용한다.

```json
{
  "sentences": [
    {
      "text": "중립적인 핵심 설명",
      "paragraphIds": ["p-00012"]
    }
  ]
}
```

## 검증 게이트

서버는 AI 출력을 저장하기 전에 다음 조건을 모두 확인한다.

1. `sentences`가 1개 이상 3개 이하이다.
2. 모든 문장의 `text`가 비어 있지 않다.
3. 모든 문장이 문단 ID를 1개 이상 가진다.
4. 모든 문단 ID가 이번 요청에 포함된 동일 판례 문단에 존재한다.
5. 출력에 사건번호·법원·날짜·URL 등 AI가 생성해서는 안 되는 메타데이터가 없다.
6. 판결 결과 예측, 사용자에 대한 법률 판단, 신고·고소 가능성 표현이 없다.

하나라도 실패하면 일부 문장만 저장하지 않고 요약 전체를 폐기한다. 판례 레코드와 검색 결과는 유지하며 `summary=null`로 처리한다.

## 검색 결과 연결

키워드·사실 태그 검색과 임베딩 검색 모두 현재 판례 원문 해시와 일치하는 저장 요약만 함께 조회한다. 서버 응답은 문단 ID를 `판결문 문단 N` 형식의 `sourceAnchor`로 변환한다.

프런트엔드는 다음을 적용한다.

- 검증된 요약이 있을 때만 `AI 생성 요약` 영역을 표시한다.
- 각 문장 아래에 근거 문단 위치를 표시한다.
- `AI가 판결문을 요약한 내용입니다. 정확한 내용은 공식 원문을 확인하십시오.` 문구를 유지한다.
- 요약이 없으면 기존 닮은 점·다른 점과 공식 원문 링크만 표시한다.

## 오류 처리

- API 키나 요약 모델 설정이 없으면 backfill을 네트워크 호출 전에 중단한다.
- 한 판례의 AI 호출 또는 검증이 실패해도 다음 판례를 계속 처리한다.
- 실행 결과로 `selected`, `generated`, `skipped`, `failed` 수를 출력한다.
- AI 원본 응답과 판결문 전체를 일반 로그에 남기지 않는다.
- 사용자 검색 API는 요약 생성 API를 호출하지 않는다.

## 테스트 기준

- 동일 판례의 실제 문단 ID를 참조한 1~3개 문장은 통과한다.
- 존재하지 않는 문단, 다른 판례 문단, 빈 근거 배열, 빈 문장, 4개 이상 문장은 전체 거부한다.
- 잘못된 JSON과 AI 호출 실패는 저장하지 않고 `failed`로 집계한다.
- 동일 해시·버전·모델은 재생성을 건너뛴다.
- 변경된 원문 해시의 기존 요약은 검색 결과에 포함하지 않는다.
- 공식 사건정보와 URL은 기존 DB 값에서만 반환한다.
- 요약이 있는 결과에는 AI 표시와 원문 확인 안내가 보이고, 요약이 없는 결과에는 요약 영역이 없다.

## 제외 범위

- 사용자 사례에 맞춘 개인화 요약
- 검색 요청 중 실시간 요약 생성
- 법률 결과·유무죄·신고 가능성 예측
- 대화 캡처 OCR 및 첨부파일 요약
- 관리자용 요약 편집 UI
