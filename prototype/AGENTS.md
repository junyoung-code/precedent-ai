# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

The approved visual direction is a calm Korean legal-AI workspace: white rounded application shell on a warm ivory-gray background, slim left navigation, black typography, and restrained walnut/caramel brown accents. The landing uses one spacious, ChatGPT-like composer capped at 1040px, with a 150px text area and the `피해자 | 피신고인` segmented control embedded in its bottom toolbar. Use generous spacing between the hero emblem, headline, supporting copy, and composer; short desktop viewports may reduce outer whitespace but must keep the composer controls visible. Mobile scrolls normally and stacks the composer toolbar into two rows. Replace the large pre-use AI disclosure card with the compact line `AI가 공개 판례를 검색·비교합니다.`, and keep each AI-authored precedent summary labeled `AI 생성 요약` with an official-source reminder. Results remain in the same document flow and scroll into view smoothly, while `prefers-reduced-motion` uses immediate movement. Do not show quick-example controls. The hero emblem uses the user-approved first generated asset: a small, centered wooden gavel and complete sound block at a moderately raised angle inside a warm brown circular medallion. The product must say `사실관계 유사도`, never legal-outcome or complaint-success probability. Never display a precedent unless its case number, court, date, source anchors, and official law.go.kr URL are present in the verified local dataset.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.
